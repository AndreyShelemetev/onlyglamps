# Импорт данных с `vsaunah.ru`: маппинг полей и дедупликация

Документ описывает, как сопоставить данные публичных карточек `vsaunah.ru`
(каталог городских саун и бань) с моделью `GlampingObject` в OnlyGlamps,
и какие ограничения нужно учесть. **Это спецификация для отдельной задачи
импортёра.** Базовые правила берём из
[competitor-import-mapping.md](competitor-import-mapping.md); ниже — только
отличия и решения, специфичные для `vsaunah.ru`.

> Юридическая рамка та же, что в основном doc: импортируем **только
> структурированные факты** (название, тип, регион/город, координаты,
> вместимость, удобства, ссылка на источник). НЕ импортируем фото, описания,
> правила, отзывы, рейтинг, контакты. Все объекты создаются со `Status = Draft`,
> `OwnerId = system`, заполненным `SourceLink`. В футере `vsaunah.ru` прямо
> указано: «использование материалов только при активной ссылке на сайт».

---

## 0. ⚠️ Блокеры, которые надо решить ДО импорта

Эти три пункта определяют, можно ли вообще импортировать конкретный объект.
Решение по ним принимает владелец продукта, не импортёр.

1. **Модель цены не совпадает.** `vsaunah.ru` — это **почасовая аренда саун**
   (`₽/час`, «минимум 2 часа»). У `GlampingObject` тариф — **посуточный**.
   Конвертация час→сутки недопустима (исказит сортировку и фильтры
   `price_from`/`price_to`). **Решение:** при импорте `Tariff` НЕ создаём,
   `MinPrice` остаётся `null`; в `ModerationComment` пишем исходную часовую цену
   как справку. Правильную посуточную цену вносит владелец после клейма карточки.

2. **Регион/город отсутствуют в каталоге.** `vsaunah.ru` — это Москва и города
   на поддоменах (`balashiha.`, `kazan.`, …), разрезанные по округам / районам /
   метро / улицам. В текущем сидере таких регионов (`Москва`, `Московская
   область`) **нет** — есть только Марий Эл, Татарстан, Нижегородская обл. и т.д.
   По правилу «импорт НЕ создаёт новые регионы/города/типы» (см. AGENTS.md и §7
   основного doc) такие объекты импортировать **нельзя** без отдельной задачи на
   сидинг региона. **Решение:** импортируем только те объекты, чей регион/город
   уже существует в БД; остальные — пропускаем и логируем. Расширение географии —
   отдельная задача.

3. **Сегмент контента иной.** `vsaunah.ru` — городские сауны на час, а OnlyGlamps
   позиционируется как **загородный отдых посуточно**. Даже корректно
   импортированные объекты могут не вписаться в SEO-таргетинг каталога.
   **Решение:** все импортированные объекты остаются `Draft` и публикуются
   только после ручной модерации; массовая автопубликация запрещена.

## 1. Источники сигнала на карточке

В отличие от `глэмпинги.рф`, у `vsaunah.ru` на карточках **нет JSON-LD**
со схемой `LodgingBusiness`. Поэтому приоритет источников такой:

1. `<title>` / `<h1>` — название.
2. Блок «О зале» / «Характеристики зала» — тип парной, вместимость, цена «от»,
   адрес, метро/район, график работы.
3. `<meta property="og:*">` — заголовок, описание (только для эвристик, не пишем).
4. Карта «Как добраться» — координаты (если доступны в DOM/атрибутах карты).
5. Списки URL карточек — из sitemap (см. §3), **только URL, не данные**.

Если поля нет ни в одном источнике — **не выдумываем**, оставляем `null`.

## 2. Маппинг полей (отличия от основного doc)

| Источник (DOM `vsaunah.ru`)                       | OnlyGlamps `GlampingObject`        | Примечание |
|----------------------------------------------------|-------------------------------------|------------|
| `<h1>` / `<title>` без хвоста «отзывы»/«в Москве»  | `Name`                              | trim, без HTML |
| —                                                  | `Slug`                              | генерируем через `SlugService` |
| всегда «Баня»                                      | `ObjectTypeId` → `bani`             | см. §2.1 |
| поддомен / город из адреса                          | `RegionId`, `CityOrDistrictId`      | только если уже есть в БД (см. блокер №2) |
| «Москва, <улица>, <дом>» из блока «О зале»          | `Address`                           | строка целиком |
| координаты карты «Как добраться»                    | `Latitude`, `Longitude`             | только при валидных значениях и bbox РФ |
| «Вместимость: N чел.» / «до N чел.»                 | `Capacity`                          | обязательно > 0, иначе пропуск объекта |
| «от X ₽/час»                                        | **НЕ импортируем как `Tariff`**     | пишем в `ModerationComment`, см. блокер №1 |
| «График работы: круглосуточно / Вт-Вс …»            | —                                   | не импортируем (часто длинный текст) |
| блок «Характеристики зала» (бассейн, кальян, …)     | `ObjectAmenity` через `Amenity.Slug`| см. словарь §2.2; неизвестные игнорируем |
| фото с `cdn.vsaunah.ru`                              | `Photos`                            | **не импортируем** |
| отзывы / оценки «10,0 Интерьер …»                   | `Reviews`, `Rating`                 | **не импортируем** |
| URL карточки (нормализованный)                      | `SourceLink.SourceUrl`              | уникальный ключ дедупликации |
| домен (с поддоменом города)                          | `SourceLink.SourceName`             | например `vsaunah.ru` / `kazan.vsaunah.ru` |
| —                                                   | `SourceLink.SourceType`             | `"competitor"` |
| —                                                   | `Status`                            | всегда `Draft` |
| —                                                   | `OwnerId`                           | системный `imported@onlyglamps.local` |

### 2.1 Маппинг типа

Все объекты `vsaunah.ru` — сауны/бани → `ObjectType.Slug = "bani"`
(в сидере: `Баня`, slug `bani`). Новый тип НЕ создаём.

### 2.2 Словарь удобств (нормализация под актуальные slug'и сидера)

Строки приводим к нижнему регистру, без пунктуации, матчим по подстроке.
Slug'и сверены с `DataSeeder.cs` (актуальные, в отличие от старого doc):

| Подстрока в источнике                         | `Amenity.slug` |
|------------------------------------------------|----------------|
| `бассейн`, `аквазона`, `купель`, `гидромассаж`| `chan`         |
| `баня`, `сауна`, `парная`, `хаммам`, `финская`| `banya`        |
| `мангал`, `барбекю`, `bbq`                     | `mangal`       |
| `wi-fi`, `wifi`, `интернет`                    | `wifi`         |
| `парковка`, `parking`                          | `parkovka`     |
| `беседка`                                       | `besedka`      |
| `река`, `озеро`, `пруд`, `на берегу`           | `u-vody`       |
| `лес`                                           | `u-lesa`       |
| `можно с питомц`, `pet`                         | `s-pitomtsami` |
| `с детьми`, `детск`, `семей`                    | `s-detmi`      |
| `кухня`, `бар`, `своя еда`, `банкетн`          | `kuhnya`       |

> Удобства, которых нет в сидере (караоке, бильярд, кальян, настольный теннис,
> массаж, проектор и т.п.) — **игнорируем**, но логируем (строка + URL) для
> возможного расширения словаря отдельной задачей. В БД их не пишем.

## 3. Сбор списка карточек (sitemap)

`vsaunah.ru/sitemap.xml` — это `sitemapindex`, который ссылается на:

- `sitemap_main.xml` — статические страницы (не интересуют).
- `sitemap_catalog.xml` — **карточки объектов** (основной источник URL).
- `sitemap_<город>.xml` (`sitemap_bronnicy.xml`, `sitemap_vidnoe.xml`, …) — по
  городам Подмосковья.
- Поддомены городов (`kazan.vsaunah.ru` и т.д.) имеют **свои** `sitemap.xml`.

Алгоритм: тянем `sitemapindex` → собираем `*catalog*` и по-городные карты →
извлекаем `<loc>` карточек → нормализуем URL (см. §4 основного doc) → фильтруем
по блокеру №2 (есть ли регион/город в БД) → парсим карточку.

> Не парсим `/search/...` URL (фильтры) — это листинги, не объекты.

---

## 4. Дедупликация

Полностью наследуется из §3 основного doc. Дополнительно для `vsaunah.ru`:

- Ключ №1 — нормализованный `SourceLink.SourceUrl` (с учётом поддомена города).
- Один физический объект может присутствовать и на основном домене, и на
  городском поддомене — считаем дублем по совпадению `Name` + `Address`
  (нормализованных) в пределах одного `RegionId`.

---

## 5. Что НИКОГДА не импортируем (дополнение)

К списку из §5 основного doc добавляется специфика `vsaunah.ru`:

- **Часовые цены** как `Tariff` (несовместимы с посуточной моделью).
- График работы, «спецпредложения», тексты «О сауне».
- Поддоменную SEO-структуру (округа/метро/улицы) — не создаём под неё маршрутов.

---

## 6. Definition of Done для задачи импортёра

- [ ] Скрипт собирает URL карточек из `sitemap_catalog.xml` и по-городных карт.
- [ ] Объект с несуществующим в БД регионом/городом — пропускается и логируется.
- [ ] `ObjectType` всегда `bani`; новые типы/регионы/города не создаются.
- [ ] `Tariff` не создаётся; часовая цена уходит в `ModerationComment`.
- [ ] Фото/описания/отзывы/контакты не импортируются.
- [ ] Все объекты `Status = Draft`, заполнен `SourceLink` (`SourceType=competitor`).
- [ ] Дедупликация по `SourceUrl` и по `Name`+`Address`+`Region`.
- [ ] Sitemap, slug-логика, canonical и robots **не меняются** (см. AGENTS.md).
- [ ] Dry-run режим: вывод JSONL без записи в БД (как у `mirturbaz`-импорта).
