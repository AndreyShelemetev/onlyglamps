# Импорт данных с конкурентов: маппинг полей и дедупликация

Документ описывает, как сопоставить данные публичных страниц-конкурентов
(в частности `глэмпинги.рф`) с моделью `GlampingObject` в OnlyGlamps,
и как избегать дублей. **Это спецификация для Task 7 (MVP-импортёр).**

> Юридическая рамка. Импортируем только структурированные факты
> (название, тип, регион/город, координаты, вместимость, удобства,
> цена «от», ссылка на источник). НЕ импортируем фото, длинные описания,
> отзывы, скан/копию каталога — это объекты авторского права. Все объекты
> создаются в статусе `Draft` со ссылкой `SourceLink` и публикуются
> только после ручной модерации/обогащения владельцем.

---

## 1. Источники сигнала на странице конкурента

Приоритет источников полей (по убыванию надёжности):

1. `<script type="application/ld+json">` со схемой `LodgingBusiness`,
   `Hotel`, `BedAndBreakfast`, `Campground`, `VacationRental`.
2. `<meta property="og:*">` (заголовок, описание, локация).
3. Микроразметка hCard / breadcrumbs.
4. DOM-эвристики (заголовок `h1`, табличка цен, список удобств).
5. Sitemap (`/sitemap.xml`) — только URL карточек, не данные.

Если ни в одном источнике поля нет — **не выдумываем**, оставляем `null`.

## 2. Маппинг полей

| Источник (JSON-LD / DOM)                             | OnlyGlamps `GlampingObject`         | Примечание |
|------------------------------------------------------|--------------------------------------|------------|
| `name`                                               | `Name`                               | trim, без HTML |
| —                                                    | `Slug`                               | генерируем сами по `SlugService` |
| `description` (короткая) / `og:description`          | `ShortDescription`                   | ≤ 280 символов, без копипасты длинных текстов |
| —                                                    | `FullDescription`                    | **не импортируем** (копирайт) |
| `@type` → маппинг                                    | `ObjectTypeId`                       | см. таблицу ниже |
| `address.addressRegion`                              | `RegionId` (через `Region.slug`)     | нормализация: «Московская область» → `moskovskaya-oblast` |
| `address.addressLocality` / breadcrumbs              | `CityOrDistrictId`                   | нормализация slug; если не найдено — берём «Прочее» по региону |
| `address.streetAddress`                              | `Address`                            | целиком, как строка |
| —                                                    | `Settlement`                         | если есть посёлок отдельно от города |
| `geo.latitude`, `geo.longitude`                      | `Latitude`, `Longitude`              | `double`, валидируем диапазон |
| `numberOfRooms`                                      | `Rooms`                              | |
| `occupancy.maxValue` / «до N гостей»                 | `Capacity`                           | обязательно > 0 |
| «N спальных мест»                                    | `Beds`                               | |
| «N м²» / `floorSize.value`                           | `Area`                               | |
| `checkinTime` / «заезд с HH:MM»                      | `CheckInTime`                        | строка `HH:mm` |
| `checkoutTime` / «выезд до HH:MM»                    | `CheckOutTime`                       | строка `HH:mm` |
| Текстовые правила («можно с детьми/питомцами», ...) | `ChildrenAllowed`/`PetsAllowed`/...  | парсим по словарю; неизвестно → `false` |
| —                                                    | `Deposit`, `Rules`                   | **не импортируем** (часто длинный текст) |
| Прайс «от X ₽/сутки»                                 | `Tariff` (1 шт., `Name="Минимальная цена"`, `Price=X`) | один тариф-«от», без подробной разбивки |
| `amenityFeature[].name` / список из DOM              | `ObjectAmenity` (через `Amenity.Slug`) | см. словарь ниже; неизвестные удобства игнорируем |
| Фото                                                 | `Photos`                             | **не импортируем**; пользователь добавит свои |
| Отзывы / `aggregateRating`                           | `Reviews`                            | **не импортируем**; рейтинг не показываем без отзывов |
| URL карточки                                         | `SourceLink.SourceUrl`               | уникальный ключ, нормализованный |
| Домен карточки                                       | `SourceLink.SourceName`              | например, `глэмпинги.рф` |
| —                                                    | `SourceLink.SourceType`              | `"competitor"` для импорта, `"owner"` для ручных |
| —                                                    | `Status`                             | всегда `Draft` после импорта |
| —                                                    | `OwnerId`                            | системный пользователь `imported@onlyglamps.local` (создать сидером) |

## 3. Дедупликация

Перед записью объект считается дублем, если выполняется **любое** из условий:

1. `SourceLink.SourceUrl` уже существует (после нормализации URL: lower-case host, без query, без trailing slash).
2. Совпадение `Name` (case-insensitive, без пунктуации) **И** `RegionId` **И** одно из:
   - `CityOrDistrictId` совпадает, либо
   - расстояние между координатами < 500 м (если у обоих есть `Latitude`/`Longitude`).
3. Совпадение нормализованного `Address` (без индексов и лишних запятых) в пределах одного `RegionId`.

Действие при дубле: **не создавать** новый `GlampingObject`, обновить только
`SourceLink` (`UpdatedAt`, при необходимости — добавить второй источник как
запись в логе импорта; одна-к-одной связь не нарушаем).

Жёстких уникальных индексов в БД сейчас нет — дедупликация делается на стороне
импортёра до сохранения. Кандидат на индекс в будущей миграции:
`SourceLink(SourceUrl) UNIQUE`.

## 4. Нормализация

- **URL источника:** `host` → lower-case, выкидываем `?utm_*`, выкидываем `#fragment`,
  убираем trailing `/` (кроме root). Идём через `Uri.TryCreate`.
- **Названия региона/города:** прогоняем через `SlugService.Generate(name)` и сверяем
  с существующими `Region.Slug` / `CityOrDistrict.Slug`. Если не нашли — НЕ создаём
  новый `Region` автоматически, объект помечаем `Status=Draft` + `ModerationComment`
  «не определён регион/город».
- **Цена:** убираем пробелы, `₽`, `руб`, заменяем «от» → 0; берём минимальное число
  > 0 как «от».
- **Координаты:** только если оба `lat`/`lon` валидны (`-90..90`, `-180..180`)
  и попадают в bounding box РФ (`41..82, 19..180`).

## 5. Что НИКОГДА не импортируем

- Фото и видео.
- Полные описания, тексты правил, индивидуальные FAQ.
- Имена и тексты отзывов, рейтинг.
- Контакты владельца (телефон, email).
- Цены конкретных тарифов с детальной разбивкой по сезонам/услугам.

Эти поля заполняет владелец в личном кабинете после клейма карточки.

---

## 6. Жизненный цикл импортированной карточки

1. Импорт → `Status = Draft`, `OwnerId = system`, `SourceLink` заполнен.
2. Карточка **не показывается** в публичных листингах (фильтр уже `Status=Published`).
3. Внутренний раздел `/dashboard/admin/imported/` (Task 7) — для модерации.
4. После клейма владельцем `OwnerId` меняется, `Status → OnModeration`.
5. После публикации `SourceLink` **сохраняется** как «откуда узнали» (для аналитики), но
   на публичной карточке не отображается.

---

## 7. Связь с SEO-правилами (AGENTS.md)

- Импорт **не создаёт** новых регионов/городов/типов — значит не создаёт новых
  индексируемых маршрутов. Sitemap не меняется без отдельной задачи.
- Карточки в `Draft` отдают 404 на публичных URL — это исключает индексируемые
  дубли с конкурентом до ручной публикации.
- Поле `SeoTitle` / `SeoDescription` НЕ заполняем при импорте (генерится дефолт
  из `Name` + регион).
